# v2.2.0 — Validated against EPA's own programs; the archival release

The release the PyAERMOD manuscript (Journal of the Air & Waste
Management Association, in preparation) cites. It carries everything
since v2.0.0 (v2.1.0 was never tagged): the validation of the regulatory
math and file formats against EPA's programs, a runstream reader that
handles every AERMOD v26135 keyword, the round-trip guarantee over EPA's
whole test-deck archive, and an AERSCREEN wrapper that drives the real
binary. Three dataclasses changed their fields incompatibly; read the
upgrade notes before pinning.

## Highlights

- **Every AERMOD v26135 keyword is read into a field or kept verbatim
  by a documented decision.** The reader went from 59 to 115 handled
  keywords over four tranches: the restart, NOx-background and
  design-value keywords (#10); AREAPOLY, BUOYLINE and RLINEXT
  construction with the group, unit and barrier keywords (#13); receptor
  networks and the runstream layout as `reset.f` and `setup.f` define
  them, MAXIFILE, several urban areas and `AERMODProject.unparsed_lines`
  (#14); the EV pathway, the last ME and OU keywords, METHOD_2, PLATFORM
  and the POINTCAP, POINTHOR and SWPOINT sources (#15). Field layouts
  come from EPA's Fortran through `scripts/keyword_oracle.py`, and
  thirty probe decks under `scripts/oracle_decks/` record what AERMOD
  said about each form, including the guesses it rejected.
- **The writer forms that were fatal in every AERMOD release are gone.**
  Every polar grid pyaermod wrote had zero receptors (`GDIR init num
  delta` where AERMOD reads `num init delta`); `MODELOPT ... ELEVATED`,
  `NO2STACK` under ARM2, a single name-first `URBANOPT`, `MAXIFILE
  filename`, the `METHOD` deposition line, four-field `EVENTPER`, the
  AREAPOLY centroid LOCATION and the group-less `BLPINPUT` were all
  rejected by the binary. Each is now written as the Fortran reads it
  and checked by AERMOD's own setup pass in the test suite.
- **The regulatory math was wrong and is now exact.** NAAQS design
  values interpolated quantiles instead of reading the rank tables in 40
  CFR 50 (understating the NO2 design value at 72 of 72 receptors on
  EPA's data); PM2.5 and PM10 scored each day by its peak hour; BPIP had
  no structure influence zone, backwards rotation and centroid XBADJ
  and YBADJ. All are pinned against EPA's own outputs.
- **AERSURFACE and AERSCREEN drive the real binaries.** Both wrote
  decks their programs never read. `AERSURFACEConfig` produces the
  pathway deck AERSURFACE parses and reproduces EPA's RDU reference;
  `AERSCREENConfig` answers AERSCREEN's interactive prompts or writes
  its restart header, with `scripts/build_aerscreen.sh` and a checked-in
  patch that makes EPA's source build under gfortran.
- **Provenance and reproducibility.** The parity report stamps the
  AERMOD version, compiler, reference set, pyaermod version and commit;
  the EPA parity, real-binary and AERSCREEN workflows run weekly; the
  report, the audit and the benchmarks regenerate from the tag with the
  commands in [docs/validation.md](../validation.md).
- **Citable.** `CITATION.cff` (CFF 1.2.0) ships with the release; the
  Zenodo DOI minted for this tag is recorded there and in the README
  once the release is published.

## Breaking changes

1. **`AERSURFACEConfig`** — the fields describe AERSURFACE's real
   control file (`land_cover_file`, `zo_radius_km`, `seasons`,
   `moisture`, `sectors` as `(start, end, "AP"|"NONAP")` triples,
   `sfcchar_file`). An old field name raises a `TypeError` naming the
   replacement.
2. **`AERSCREENConfig`** — the fields are AERSCREEN's prompts
   (`vertical_dimension`, `lateral_dimension`, `land_use` with
   `climate`, `dem_files`); `distances` and `extra_lines` are removed.
   An old field name raises a `TypeError` naming the replacement.
3. **`EventPeriod`** — AERMOD's five `EVENTPER` fields (`event_name,
   averaging_period, date, source_group, original_conc`) plus a required
   `location=EventLocation(...)`; `write(event_filename=)` writes a
   complete event deck.
4. **`OutputPathway.max_file` is removed**; use
   `maxi_files=[MaxiFile(...)]`. `GasDepositionParams` has AERMOD's
   field names (`diffusivity`, `diffusivity_water`,
   `cuticular_resistance`, `henry_constant`). `deposition_method` is
   kept but writes nothing; Method 2 deposition is `method_2`.

The full mapping and before/after examples are in the upgrade notes of
`CHANGELOG.md`.
